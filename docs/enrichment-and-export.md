# Enrichment and export (M4)

## Enrichment
- `EnrichmentService.enrich(principal, {contactId})` needs `contacts:enrich`. Unknown contact -> `NOT_FOUND` (no provider call, no record).
- Each call asks the provider again and inserts an `enrichment_records` row (also for NOT_FOUND and FAILED). Nothing is cached or deduplicated.
- Status is derived from the returned fields: both -> SUCCESS, one -> PARTIAL, none -> NOT_FOUND. A provider that throws -> a FAILED record and `PROVIDER_ERROR` with a generic client message. The raw cause is persisted and logged only in redacted form -- see "Secret redaction" below.
- `Contact.email`/`linkedin` are written only for fields the attempt returned, so the latest successful value survives PARTIAL, NOT_FOUND and FAILED attempts.
- SUCCESS/PARTIAL write the `EnrichmentRecord` and the `Contact` update in one Prisma `$transaction` (interactive form, with tx-bound `ContactRepository`/`EnrichmentRepository` instances), so a failure partway through rolls both back. The provider call itself runs before and outside the transaction. FAILED and NOT_FOUND are each a single write and need no transaction.
- The response reports what this attempt returned, not the merged contact.

### Secret redaction
`packages/core/src/security/redact.ts` is the single source of truth for what counts as a secret shape (Bearer tokens, `aip_<keyId>_<secret>` keys, Authorization headers, connection-string `user:password@host`, and `password`/`secret`/`token`/`access_token`/`refresh_token`/`apiKey`/`key`/`credential` assignments with either `=` or `:`). Two call sites use it:
- **Persistence**: `enrichment/sanitize-error.ts`'s `sanitizeProviderError` redacts, then truncates to 300 chars, before a FAILED attempt's error text is written to `EnrichmentRecord.error`.
- **Logging**: `logging/logger.ts`'s `scrub` normalizes every logged value, recursively, into one of: `null`, a redacted string, a number, a boolean, an array, or a plain object -- the only shapes passed to Pino. `describeError` (exported for direct testing) is the dedicated path for an `Error`: it never calls Pino's standard `err` serializer on a live `Error` (that serializer concatenates an *unsanitized* `cause.message`/`cause.stack` into its own output before any redaction could run -- the original bug). Instead it builds the plain object itself -- `type`, a redacted `message`, a redacted `stack`, and a redacted `cause` (recursively, bounded to 5 levels and guarded against a circular `cause` chain) -- and no reference to the original Error or its cause survives. A `Date` becomes an ISO string; `Map`/`Set` become `{type, size, entries/values}` with every entry normalized the same way; a `Buffer`/typed array becomes `{type, byteLength}`, never its raw bytes; any other class instance becomes `{type}` only -- its fields are never read or serialized, so an unrecognized object can never smuggle a secret through untouched. A sensitive key name (`password`, `token`, `apiKey`, ...) is redacted by name at *any* depth, not only within Pino's own 2-level wildcard `redact.paths`. This runs both as a `logMethod` hook (catching any of the above anywhere in a logged object, not only under `err`) and as the registered `err` serializer, so nothing reaches Pino as a live Error or arbitrary object either way. Server-side logs still carry full diagnostic detail -- stack traces, a provider cause's message, SQL text -- deliberately (this predates M4; see `test/logger.test.ts`/`test/errors.test.ts`), just normalized and scrubbed of every known secret shape.
- Provenance has one entry per returned field: `{field, source, synthetic, verified: false, observedAt}`. Attempts that returned nothing store `[]`; the record's provider/status/createdAt describe the attempt.
- Mock provider: outcome from `sha256(contactId)` (10% FAILED, 10% NOT_FOUND, 15% PARTIAL, 65% SUCCESS), see `mockOutcomeFor`. Email is `first.last@<company>.example`; LinkedIn is `https://linkedin.example/in/synthetic-...`. No network access.

## Export
- `ExportService.export(principal, {contactIds})` needs `contacts:export`. The contract caps the array at 1000 ids (a payload-size guard, `VALIDATION_ERROR` above it); the actual business limit of 200 is enforced independently by the service (`EXPORT_LIMIT` above it). Duplicates are collapsed; rows follow request order. Any unknown id fails the whole request with `NOT_FOUND` listing all of them.
- Columns: `id,name,title,email,linkedin`, CRLF line endings. Cells starting with `= + - @ TAB CR` get a leading `'`.
- Token: 32 random bytes (base64url). Only the SHA-256 is stored. The URL is `<downloadBaseUrl>/downloads/<token>` and is returned once.
- `download(rawToken)` needs no principal: the token is the credential. Malformed, unknown and expired tokens all give the same `NOT_FOUND`. Valid for 15 minutes.
- Expired rows are deleted before each new export and by `purgeExpired()`. The CSV is stored in `export_jobs.content`.
